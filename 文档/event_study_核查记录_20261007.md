## 结论：需要补2017年行情

脚本第42行定义 `EST = (-120, -11)`；第85—91行在事件位置之前取这段行情的对数成交量均值，作为事件当天异常成交量的基准。这是110个位置，最早需要往前120个位置。

严格说，代码按个股表的行序切片，而不是按交易所日历定位。只有先统一交易日历、排除非交易日填充并正确处理停牌及缺失日期，位置才可以解释为交易日。

因此，为保留2018年初事件的合理事前样本，应补2017年股票行情。按已下载指数日历、暂以首个不早于报告日的交易日对齐，1,663条事件（800只股票）的事前120日可能跨入2017年。这只是数据需求筛查，不等于这些事件都能获得完整基准；新上市股票或缺失、停牌仍须单独检查。

同时补2017年沪深300指数，以便脚本通过前一期收盘指数计算2018年第一个交易日的市场回报，并为潜在事前窗口保留统一日历。

## 脚本实际计算了什么

| 项目 | 代码行为 | 原脚本位置 |
|---|---|---|
| 短期CAR | [-1,+1]、[-1,+5]、[-5,+5] | 第38—40行 |
| 长期CAR | [0,+60]、[0,+120]、[0,+250]，含两端；[0,+250]为251个位置 | 第38—40、78—82行 |
| 正常/基准收益 | 由指数收盘价的相邻变化计算，不拟合alpha、beta | 第69—72行 |
| 异常收益 | 股票百分数涨跌幅减市场百分数回报 | 第72行 |
| 异常成交量 | 事件当天log(成交量)，减去[-120,-11]期log(成交量)的平均值 | 第73、85—91行 |
| 事件日 | 只与最新报告日期精确匹配；没有自动顺延 | 第107—109行 |
| 分组检验 | 每个star×评级方向组内均值相对0的单样本t检验 | 第128—136行 |

尽管第41行注释写“估计窗口（算正常收益用）”，EST实际上只用于成交量基准；这版不是市场模型回归。长期CAR是每日异常收益相加，不能直接称为买入持有复利超额收益；而且长期窗口包含公告反应本身，尚未单独隔离事后漂移或反转。

## 运行前必须明确的问题

### 1. 非交易日报告会被跳过

将分析表的 20,980 条事件与沪深300交易日历核对，有3,857条报告日期不是交易日。若行情只保留交易日，原脚本第107—109行会跳过这些事件。年份计数：2018年628、2019年545、2020年506、2021年432、2022年597、2023年626、2024年523。

不能为让它们匹配而保留CSMAR节假日填充行，否则交易日窗口与市场收益匹配会出错。应由团队确认事件对齐规则，并保留原报告日、另设事件交易日；仅有报告日期时，首个不早于报告日的市场交易日是一种待确认的规则。若有发布时间，还需考虑盘后发布。当前没有擅自调整事件日期。

明细：`event_study_非交易日报告_需确认事件对齐.csv`（待行情侧提供）。其中候选交易日仅供审核，不是已经批准的事件日。

### 2. 停牌、缺失与节假日不能用同一种删除方法

原脚本没有读取Filling、StateCode，也没有在市场交易日历上重建窗口。保留节假日填充会多算位置；直接删掉停牌或缺失行会少算位置，导致“250行”跨越250个市场交易日。需要团队确认停牌事件的处理以及有效观测门槛，保留状态审计字段，不把未知缺失自动补零。

成交量为0或缺失时logV成为缺失值，基准均值默认跳过缺失。脚本没有要求110个基准位置都具有有效成交量，也没有设置最少有效样本数。

### 3. CAR会跳过缺失值求和

第82行直接 `.sum()`。Pandas默认忽略缺失值，甚至全缺失序列也可以得到0。因此“窗口行数足够”并不表示收益数据完整。应增加窗口有效观测数量校验，未满足要求时返回缺失并记录原因，不能把缺失当零回报。

依据：[Pandas Series.sum 官方文档](https://pandas.pydata.org/docs/reference/api/pandas.Series.sum.html)。

### 4. ST注释不是可靠识别方法，也没有实现

第9行提出从5%涨跌幅反推ST，但单日涨跌幅不能唯一确定股票的ST身份。当前脚本也没有任何ST识别或过滤逻辑。不能声称这版结果已经控制或剔除了ST；如果团队需要该处理，应另外使用按日期生效的历史状态数据。

### 5. 输出还不足以完成全部研究问题

- 第111—114行没有将资历、资历分位或券商层级写入事件级结果，虽然加载的事件表含这些字段。后续控制变量分析要通过稳定事件ID或可靠联合键保留/关联，不能仅靠股票和日期匹配多个分析师事件。
- 分组单样本t检验回答“每组是否不同于0”，没有直接检验明星与非明星组的差异，也未处理同股同日事件的相关性。
- AV只计算事件当天，不是[-1,+5]窗口的逐日异常成交量路径或窗口汇总。

以上为核查发现，尚未擅自修改研究引擎或替团队决定方法。

## 可确定的数据交付格式

`market_panel.csv` 至少含：股票代码、日期、收盘价、涨跌幅、成交量。

- 股票代码保持与事件表一致的带交易所后缀标识；300114历史行情需另行映射到302132.SZ用于事件匹配，同时保留原始代码追溯。
- 日期用YYYYMMDD字符串，按股票代码、日期排序并验证唯一性。
- CSMAR ChangeRatio乘100后进入“涨跌幅”；Volume已经是股数，无须乘100。
- ClosePrice原样保留为前复权价格，但300114/302132跨代码复权基准问题继续保留标记。当前脚本的CAR使用“涨跌幅”，没有用个股“收盘价”计算收益；因此该接缝不直接进入这版CAR，但其他基于价格计算的长期收益仍须核对。
- 节假日填充不能进入交易日面板；停牌与缺失处理需先确认。原始状态字段应保留在审计附表或扩展面板中，不因五列接口而丢弃依据。

`index_panel.csv` 至少含：日期、收盘价。日期同样用YYYYMMDD，收盘价来自Clsindex，必须先按日期排序并去重，因为脚本在排序前就计算pct_change。原始Retindex另保留用于核验。当前指数文件已验证顺序正确。

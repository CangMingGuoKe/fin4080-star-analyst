## 一、方法口径

- 交易日历：`index_panel.csv` 中按日期升序去重，共 2,367 个交易日（20170103 至 20260930）。
- 事件日：首个不早于报告日的交易日，用 `searchsorted` 在日历上定位。20,980 条事件与 `car_event_level.csv` 的事件交易日逐条一致，不一致 0 条；事件股票在行情面板中缺失 0 条。
- 异常收益：个股当日涨跌幅减指数当日涨跌幅，两者均为百分数。
- CAR：窗口内异常收益的算术和。事件日必须有效，窗口内有效观测占比不低于 80%。`CAR_p2_p120` 的参照实现不把事件日计入窗口，这一点在第二节单独说明。
- 持有收益：从事件日收盘起，63、126、252 个交易日内的日涨跌幅算术和。市场调整版本再减去同期指数日涨跌幅之和。方向调整对调高取正、对调低取负。
- 预测误差：按股票、报告日期、分析师、机构四个字段匹配原始预测与实现 EPS，误差为 `|预测EPS - 实现EPS| / 事件日收盘价 * 100`。
- 比对阈值：CAR 与预测误差看绝对差是否超过 `1e-6`；持有收益看均值差是否超过 `0.01` 个百分点，并核对 N。

### 2.2 CAR_p2_p120 的 64 条 NaN 状态差异

这 64 条不是数值算错，而是事件日有效性的规则边界。

- 64 条全部是 `CAR_m1_p1_原因 = 事件日缺收益` 的事件。事件日当天个股涨跌幅为空，通常是停牌或无成交，因此事件日异常收益不可用。
- 这 64 条在 `+2` 到 `+120` 的窗口内有效观测为 96 至 119 个，共 119 个位置，均达到 80% 门槛。因此参照实现给出了 `CAR_p2_p120` 数值。
- 参照实现的 `window_car` 只在 `lo <= 0 <= hi` 时检查事件日有效性。`CAR_p2_p120` 的窗口是 `[2, 120]`，不包含第 0 天，所以参照实现不检查事件日。
- 本次任务要求“窗口内至少 80% 有效且事件日有效”，脚本对四个窗口一律要求事件日有效。因此这 64 条在任务口径下为 NaN，在参照口径下有值。
- 若按参照窗口规则重算，`CAR_p2_p120` 的 NaN 状态不一致降为 0，最大差仍为 `1.28e-13`。所以 64 条是定义边界，不是实现错误。

示例事件：`002697.SZ 20180102`、`002458.SZ 20180105`、`002033.SZ 20180131`。完整 64 条可按 `CAR_m1_p1_原因 = 事件日缺收益` 且 `CAR_p2_p120` 非空筛出。

## 五、首轮错误与修正记录

首轮运行发现 CAR 数值系统性偏离，持有收益和预测误差当时已与参照一致。首轮结果如下：

| 窗口 | 最大绝对差 | 平均绝对差 | 超过 1e-6 条数 |
|---|---:|---:|---:|
| CAR_m1_p1 | 18.879 | 1.6425 | 20,836 |
| CAR_m1_p5 | 29.280 | 2.526 | 20,877 |
| CAR_m5_p5 | 30.190 | 3.036 | 20,818 |
| CAR_p2_p120 | 无有效比对 | 无有效比对 | 20,915 条 NaN 状态不一致 |

原因有两处，都在本次复现代码中，不在参照代码中：

1. 计算 CAR 时只累加了个股涨跌幅，漏减指数涨跌幅。持有收益的市场调整版本另行计算，所以当时未受影响。
2. 事件日有效性标记只在窗口偏移 `k=0` 的分支里赋值。`CAR_p2_p120` 的窗口从 `+2` 开始，循环中永远不经过 `k=0`，事件日标记始终为假，导致该窗口全部为 NaN。

修正方式是先构造异常收益矩阵 `AR = 个股涨跌幅 - 指数涨跌幅`，再在窗口循环之外单独计算事件日有效性。修正后结果即本文第二节。首轮错误结果已被覆盖，`data/replication_check.csv` 中保留了一行 `audit_history / FIRST_RUN` 记录，本文也保留上表作为审计痕迹。

## 六、结论

- 事件研究：四个窗口的数值最大差在 `1.28e-13` 以内，超过 `1e-6` 的条数为 0。`CAR_p2_p120` 有 64 条 NaN 状态差异，原因是参照实现只在第 0 天位于窗口内时检查事件日有效性，而任务口径要求所有窗口都检查。按参照规则重算后，NaN 状态差异为 0。
- 持有收益：12 个分组的 N 全部一致，均值最大差 `4.94e-05` 个百分点，超过 `0.01` 个百分点的组数为 0。
- 预测误差：字面匹配 20,092 条，参照 20,248 条，差额 156 条全部来自券商写法或分析师空值的键名规范化。规范化后匹配数、事件级误差和汇总 N 全部复现，超过 `1e-6` 的条数为 0，超过 `0.01` 个百分点的汇总组数为 0。
- 可能原因集中在四类：浮点求和顺序造成的 `1e-13` 级舍入；汇总文件保留四位小数造成的 `1e-05` 级差异；券商简称与改名的键名规范化；事件日停牌时参照代码的窗口规则与任务文字要求不一致。

没有为了让结果一致而调整复现代码。首轮错误按原样记录，修正只针对复现代码自身的两处实现错误。
